Re: M13 delivered — /loaders + /static routes for the api/ (mount when ready)

loader/stub/ (Public a7beaa4) ships the M13 surface behind §5.3's two file
endpoints; the Public api/ currently has neither route. Mounting is two
router entries + a deps object (full snippet in loader/stub/README.md):

- GET /loaders/:script_id.lua  → handleGetLoader(deps, params.script_id)
  → resolveScript = active version's init_build (script_versions), 
    getInitBytes = blob read; stub is unique per fetch (CSPRNG values),
    served `no-store`.
- GET /static/init_:build.lua  → handleGetInit(deps, params.build, req.url)
  → `public, max-age=31536000, immutable` (builds are content-addressed:
  b+sha256[0:12]; new content = new URL = no invalidation ever). Optional
  injectable EdgeCache adapter over caches.default — research note: `.lua`
  is NOT in Cloudflare's default cached-extension list, so R2-custom-domain
  serving would need a Cache Rule; the Worker+CacheAPI path doesn't.

All 4xx/5xx from these handlers carry no-store (no edge-cache poisoning).
Build-id/script-id format gates are inside the handlers (traversal-proof).
One blob read per stub fetch is the baseline; memoize build→bytes per
isolate if stub traffic makes it hot (uniqueness comes from CSPRNG, not
the blob read).

Admin upload path: call packageInit(bytes, now) → store init_build +
bytes; stubs then embed that build's exact size + FNV-1a32+DJB2 and
validate cached/downloaded init bytes client-side (D12 resolved).
