# Lessons (shared/lessons.md)

Append what worked / failed / what to do differently. Mark "trusted" only after testing. Cap ~100 lines.

## Delivery & environment

- **Tool-output secret redaction is display-only** (tested: oldglm worklog grep `ghp_` count = 2 while the same lines displayed as `[REDACTED:github_token]`). A "redacted" token in a displayed file may still be live in the file itself. Verify with `grep -c` or use it via shell variable without echoing. The 2026-10-01 SCPINC session lost push ability to exactly this trap.
- **Repo delivery convention** (tested across snack/camera/towerinc commits): push the REPACKED game zip (originals byte-identical + new/updated `<Game>.lua` inside) to the Public repo root; commit message `"<game>: ..."`. Never push loose files there.
- **User closes games by deleting their zip** from the Public repo. A missing zip is not an error; TASK_SOURCE.md's table is the record. Do not resume a closed game unless the user re-opens it (explicit fix order in chat beats inference; fresh error logs alone are only a signal).
- **IM-gateway file attachments are unreliable**. The GitHub repo is the authoritative channel.

## Roblox hooking

- **Hook payload indices come from the WIRE-level namecall, not the wrapper** (tested: Snack fix 2026-10-01, harness 157/157 after correcting the model): Snack's `EasyEvents:InvokeServer(name, payload)` resolves the named remote and forwards ONLY the payload (`ensureRemote(name):InvokeServer(payload)`), so the __namecall hook sees `(self, payload)` — payload at `nargs[2]`. The Slop-ported `SnapshotCall` read `nargs[3]` → captured nothing in-game while the mock harness (which modeled the wrapper signature) stayed green. Trace the wrapper module to the raw instance call in the deobf before coding ANY hook arg indexing.
- **A green mock harness only validates the harness's protocol model.** Cross-check the model against the deobf call site — or the harness will happily pass on a protocol that never happens in-game.
- **cloneref executors (Cobalt) break rawequal(self, ScriptRef) hook gating** (tested: Alliance verified by user; Snack harness now simulates it): the script's Services-metatable refs are clones, while the game-side namecall `self` is the original → single-rawequal gate never matches → 0 captures despite a healthy "hook installed" log. Fix: OrigRemotes table filled from a FRESH `game:GetService("ReplicatedStorage")` (bypasses the cloneref'd Services cache) + double-rawequal check (OrigRemotes first, then script refs). Harness pattern: make cloneref return a proxy RS for the script, keep originals for game-side calls.
- **hookfunction on RemoteFunction:InvokeServer does not intercept `:`-syntax calls** on some executors; `__namecall` hookmetamethod is the only reliable primary hook. "hook installed" != "hook fires". Supplementary hookfunction must target the ORIGINAL's method (OrigRemotes.X.InvokeServer) and dedupe via a namecall-seen marker (NCSeen).
- **Original-first capture + post-state reads**: snapshot AFTER `originalNamecall(...)` sees server-mutated state (mock server bumps tower Level during the original call). For "resulting level" semantics read post-state WITHOUT `+1`; for pre-state semantics snapshot before the original. Snack Upgrade LVL = resulting level (tier index + replay skip level) — post-read, no +1.

## Lua/harness mechanics

- **Lua 5.4 vs Luau**: `unpack`/`table.clone`/`string.split` are Luau-only — harness must shim; scripts must not depend on them (GLM rules).
- **Shared.Labels = {} must be initialized first** in every game section (TowerInc crash class — whole section dies at first SafeLabel).
- **Fast SafeInvoke changes test timing** (tested: Snack harness 2026-10-01): replacing a poll-until-timeout invoke (2 virtual sec/iteration) with a done-flag invoke lets loops complete MANY iterations per pump — tests that reused state across phases (towers left at max level) silently broke. Reset world state between test phases.
- **Mock instances need every method the script calls** — `FindFirstChildOfClass` was missing from the mock Inst and every GetCharacter() call silently error'd inside pcalls for sessions (only surfaced when a test finally asserted on a TP position). Grep the script for `:FindFirstChildOfClass(` etc. when extending mocks.
- **Tool display can eat `[m` character pairs** — `slotByName[model.Name]` displays as `slotByNameodel.Name]` in tool output while the file bytes are correct. Verify suspicious "corruption" with `rg`/`od` on the raw file before "fixing" it.
- **unzip CLI glob-matches member names** (tested: repack.sh negative path 2026-10-01): `unzip -p archive "[UPD 2] SCP/x.lua"` treats `[...]` as a character class → "filename not matched" → empty output → md5 of EMPTY input (d41d8...) on BOTH sides of a before/after check = vacuous pass. Use python3 zipfile for any zip member handling with bracket/space names.
- **Harness Instance mock: `child.Parent = parent` does NOT register children** (tested: harness_lib smoke 2026-10-01) — only `parent:AddChild(child)` populates `_children`; plain Parent assignment makes FindFirstChild*/GetChildren silently return nothing. Same silent-gap class as the missing FindFirstChildOfClass. `shared/tools/harness_lib.lua` header documents all three gotchas; start new game harnesses from it.
- **Result-table values are snapshots** (tested: harness_lib smoke 2026-10-01): a mock script writing `g.__Result = { hits = hits }` copies the number at write time — later mutation checks must use getter closures (`g.__GetHits = function() return hits end`), not re-read table fields.
- **`task.spawn` runs the body immediately until first yield** (Luau semantics, mirrored by the harness scheduler) — a "loop started" check right after SetValue sees the first pass already executed. Write assertions accordingly (>= not ==).

## Tooling (shared/tools/)

- **Python zipfile `writestr(zinfo, data)` MUTATES the ZipInfo you pass it** (header_offset, CRC, sizes). If you pass ZipInfo objects taken from the SOURCE archive's `infolist()`, you corrupt the source's cached metadata and every later `read()` dies with `BadZipFile` — content was fine all along. Always pass `copy.copy(info)`. (Found + fixed in repack_zip.py, 2026-10-01; verified originals stay MD5-identical after the fix.)
- **`table.unpack` is standard Lua 5.2+; BARE `unpack` is the Luau/5.1 one.** Lint rules must distinguish them — the canonical template legitimately uses bare `unpack` + `typeof` (executor Luau; harness shims), so Luau-only checks need a game-section line range, not whole-file bans (lua_lint.py `--from/--to`).
- **/tmp is wiped between sessions; /home/z survives.** Keep clones at /home/z/SavedFolder + /home/z/Public (poll.sh defaults there) and portable Lua at ~/.lua54 via bootstrap.sh — never recompile from source.
- **Game zip paths contain spaces AND emoji** ("[UPD 2] SCP Incremental", "MATI/Level 1 🧊" — both real). NEVER `for x in $(find ...)` / any unquoted command substitution over paths: word-splitting printed ONE folder as four broken "dirs" (tested: newgame.sh structure-notes before the T7 fix). Use `find ... | while IFS= read -r x` (or `-print0`), and quote every expansion.
- **Multi-agent CLI tools should accept flexible arg order or fail loudly** (tested: deobf_search.py T7): even the author's own description ("`remote [NAME]` usage maps") invites command-first invocation, and the original FILE-first-only parser answered that with a Python traceback. Fixed with arg-order tolerance (`FILE CMD ARGS` ≡ `CMD FILE ARGS` ≡ `CMD ARGS FILE`); general rule for shared tools — parse like a human types, and error messages should restate the usage.
- **A "successful" push is only real when `git ls-remote` shows it.** 2026-10-01: BOTH delivery pushes (SCP + snack) reported done in the worklog yet never landed on origin — discovered 2026-10-02 by pure accident when the user's next upload exposed the divergence; a delivery day was lost. Rule: every push gets verified (`git ls-remote origin HEAD` == `git rev-parse HEAD`), or better, pushed through `sync.sh` which verifies + exits 1 on mismatch. Cost of the check: ~1s. Cost of skipping: a day.
- **deobf_search `remote` map: `Fire:` rows include BindableEvents.** MATI dogfood (2026-10-02): the game's UI modules fire module-internal BindableEvents (`var3:Fire(arg1)` view propagation, trade notices) that the usage-map heuristic lists next to real `FireServer` hits. Always confirm against the Net module's own name table (search `FolderName`) before treating a `Fire:` hit as a game remote.
- **Lua vararg `...` in a NON-LAST argument position adjusts to ONE value** (tested: MATI harness 2026-10-01). `SafeInvoke(remote, false, action, ..., guid)` silently passed only the FIRST vararg — the Shop "buy" wire lost its display-id argument exactly like a §20.6 payload-index bug, and `table.pack(action, ..., guid)` has the same trap (the `...` still sits mid-list). Correct shape: expand varargs into a table, append the trailing arg, then pass `table.unpack(args)` as the LAST call argument. Same class as wire-level indexing: the harness catches it only if checks assert FULL argument tuples.

## Scope & discipline (user-flagged incidents)

- **An unasked UI element is a shipped bug** (tested: MATI status label, user-flagged 2026-10-02, removed + re-delivered as Public c2cf4a8): a live `SafeLabel` narrating the autofarm loop ("Melting"/"Recharging"/…) — no reference script had it, the template's game section has no label calls, nobody ordered it. User: *"who ask you to add the label… is the label you add helps with anything?"* Rule: every UI element traces to (a) user order, (b) reference script, (c) template — otherwise it does not ship. The toggles ARE the UI. Same class as Rule 11's "useless features" but for UI: helpful-looking ≠ asked-for. Also remove the support line when you remove the usage (Shared.Labels init, harness checks) — dead scaffolding is the same bloat.
- **"Green in the harness" is not the delivery bar; the user reviews the actual diff.** The label passed luac, lint, template diff, and its own harness check — every gate was green because the gates measure what WAS built, not what SHOULD have been built. The §2 filter (ONBOARDING) runs BEFORE the gates, on every addition.

## Stress round 2026-10-02 (10-game batch)

- **Networking framework conventions differ per game — check the wrapper's CALL SYNTAX from the deobf before building mocks** (tested: 3 games, 3 conventions): Anime Breaker = Framework Library NetworkService `lib.Remote:Fire(system, cmd, args)` (BridgeNet2 Main, packs args client-side); Clone to Steal Eggs = Knit DOT-call `Knit.GetService("X"):Method(...)` (name is arg 1 — a `(self, name)` mock silently shifts args and every wire dies while "loads fine"); Flip a House = Remo containers `require(RS.Shared.Foundation.Net.Remotes).ns.remote:fire()` (lowercase, colon) / `:request()` for promise-returning RFs. Mock signature must match the game's exact call syntax (dot vs colon) — a mismatch produces silent no-op wires, the harness catches it ONLY if checks assert wire counts.
- **A game with server-gated auto features (entitlement/gamepass) can't be "auto-farmed" by wiring the entitlement** (tested: Fishing Master AutoStateRequest/AutoStateUpdate) — the client only ASKS for auto state; the server decides. Flag to the user instead of shipping wires that gate on server-granted bools.
- **Prediction/pointer-telemetry minigames (FishReelPull needs EmitPredictedAtPointer sequences; Flip a House cleaning needs patchBatch/snapshot/predictionAck) are deep builds, not standard autofarm** — naive loops fire invalid sequences (kick risk). Scope them out at analysis time and say so in the delivery note.
- **A harness that never loads the delivered script validates nothing about it** (tested: ST-QA1 audit 2026-10-02 — glm2's three stress scripts all BROKEN AT LOAD (`TB.Main.Left.Autofarm.T1` nil — T1 is a key in the script's TB_Tabs table, never a tabbox field) while their three harnesses passed 6/6, 11/11, 5/5, because the harnesses re-implemented the game logic harness-side instead of `io.open`ing + loadstringing + spawning the actual .lua). Minimum viable harness: mock world + loadstring(ScriptSrc) + task.spawn + assert (a) no ERROR notify, (b) toggles registered, (c) wire counts + FULL payload tuples after SetValue(true) + pump. UI access canonical: `TB_Tabs.Autofarm.T1:AddToggle(...)` — never `TB.<...>Autofarm.T1`.
- **Unguarded module parents crash at early auto-exec** (tested: rt3 QA 2026-10-02): `GetSafeModule(GetObject(Plr, "PlayerScripts.Source..."), name)` — GetObject is FindFirstChild (non-yielding); if PlayerScripts hasn't replicated when the executor auto-runs, parent=nil → hard crash at line 123. Guard: `local p = GetObject(...); return p and GetSafeModule(p, name) or nil`, or bounded-retry the populate.
- **§3 scope has TWO halves — the user settled it** (2026-10-02 order to glm2: "too little features" after 1-toggle deliveries): "standard autofarm" = wire every remote that passes Rule 11's KEEP filter (the game's real automation surface) AND invent nothing beyond it. Under-shipping = over-shipping = violation. Codified in ONBOARDING §3.
- **A named reference script is a STRUCTURE spec, not just a feature list** (tested: Periastron TD 2026-10-02, user-flagged as "repeated violations" after the MATI label incident): slop.lua + the blessed Snack.lua define the function shapes (`GetUpgradableTowers`/`UpgradeCand`/`Func_AutoUpgrade`, `TryPlaceTower`+`Func_AutoPlace`, `Func_MacroRecord`/`Func_MacroReplay`, `Func_AutoAtWave`, `HandleSlotPos`/`SavePositions`/`LoadPositions`), the UI element ORDER and exact TEXTS (UpgradeMethod's four strings, "Time|Money" ReplayMode, T1 tab named "Game"), the on-disk FORMATS (per-map position lists in position.json), and even which defensive lines exist WITHOUT a UI control (slop reads `Options.UpgradeReserve` but never creates the slider — porting that line is fidelity; adding the slider is invention). When a reference exists, port its shape and deviate only where the game's verified wires force it — documenting each deviation in the analysis file. The audit that finds these: enumerate YOUR script's UI elements + functions, then grep the reference for EACH — anything absent from the reference AND absent from your analysis's sanctioned mapping table gets cut.
- **Async transport needs an in-flight dedup that sync-invoke references don't show** (Periastron, 2026-10-02): slop/Snack place towers via synchronous RemoteFunction invokes — by the time their `Func_AutoPlace` loop iterates, the tower exists. A game whose wires are fire-and-forget (`Me:Fire`) confirms via events ~50-100ms later; a frame-paced slop loop fires duplicates the whole window (overshoot past PlaceLimit, server-side reject spam). The honest port keeps slop's pacing but adds an invisible per-name in-flight guard (fire → skip name until its ReplicateUnit lands or ~1s passes), same non-UI plumbing class as the SelfFire guard. Harness must model the server's async confirm (auto-Respond to PlaceUnit with ReplicateUnit after a delay) or the check numbers are fiction.

## Stress round 2026-10-02 — ST13 (Periastron second violation round)

- **`checkcaller()` (potassium doc §12 UNC standard, from Cobalt) is the canonical "who is calling" gate for hooks** (tested: Periastron ST13, user-flagged "check caller, ever heard of that stuff?"): when a hook needs to distinguish OUR fires from the GAME's fires (macro record on Me:Fire / any Lua-table method hook / namecall captures), `not CheckCaller()` — feature-checked at startup, both spellings (`checkcaller`/`iscaller`), refusal Notify when absent (slop's Support.HookMeta precedent) — replaces ALL bookkeeping gates. The SelfFire-read hook was the §23.16 stuck-true class AND required FireGame to bypass the hook via OrigFire (a private path — slop's shape is ONE path: wrappers call the live method, the hook excludes executor callers). Also: use `type()` not `typeof()` for the feature check inside the game section (lint).
- **Your own analysis file is NOT a reference** (tested: Periastron ST13, user: "who ask you to add reexecute"): ST12 kept AutoReexec/DefeatMode alive by citing periastron-analysis.md's "sanctioned mapping table" — a document I wrote. Rule 11 references = user-named sources ONLY (slop.lua, Snack.lua, Template.lua, the GUIDE, the deobf). Self-certification is how inventions survive their own audit. When an element traces to my analysis + nothing else, cut it.
- **Template feature deletions are BANS, not suggestions** (potassium doc §14.2): the user REMOVED QueueOnTeleportExec ("do NOT re-add or re-implement these") — re-implementing it as a game-section `QueueOnTeleportExec` to serve an invented AutoReexec is a double violation. Read §14.2's removal list before building ANY feature that smells like a template capability.
- **Symmetric encode/decode = pointless invention** (user: "why the fuck did you add *1000 and divide 1000, what's the fucking point"): if you find yourself encoding at capture (`math.floor(t * 1000)`) and decoding at read (`/ 1000`), STOP — port the reference's raw format (slop: `tostring(elapsed or 0)`). Worse, the encoding masked that the consumer (Time-mode elapsed wait) was MISSING entirely — port the whole mechanism, not just the storage format. Harness now checks the format (raw seconds) AND the wait (no early fire, fires when elapsed reached).
- **Test-order matters with once-per-event guards** (harness bug found during ST13): the Win test consumed `Match.WebhookSent`, so the immediately-following GameOver test saw no webhook fire — correct script behavior, wrong test sequencing. Reset the round (RoundRestarted) between same-guard assertions.
